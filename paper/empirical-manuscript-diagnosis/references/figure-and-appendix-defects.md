# 图表与附录：压缩稿时最容易掉的两种证据

投稿前体检的最后一步，不是读文字，是看图和附件。两项都不是写作问题，是「改稿过程中丢了东西」。

## 一、图表缺陷：先分类，再逐项查

| 类 | 来源 | 特征 | 处置 |
|---|---|---|---|
| A 类：文生图造的假图 | 图像模型直接出图 | 图中文字糊或乱码、结构／解剖错误、过度光滑无真实噪声 | 不是修图，是换图。真数据重画 |
| B 类：代码画的图 | 绘图脚本 + 真数据 | 数据是真的，毛病是「没人看过成品」：默认配色、标签压数据、缺 n、截断未标、窗口未交代 | 改脚本重出 |

多数可疑图是 B 类。先查 B，别一上手就怀疑是 AI 生成的——把真数据图判成假图，是另一种误判。

### B 类十项

| 查什么 | 怎么算中 | 怎么修 |
|---|---|---|
| 图中文字可读 | 中文变方块、英文糊 | 字体与编码；PNG 逐张打开看 |
| 配色非默认 | 一套 tab10 蓝橙绿红紫 | 显式常量 |
| 误差线有定义 | 图注没说是 SD、SE 还是 95% CI | 写明算法与倍数 |
| 不用柱状图代替分布 | 连续变量只画了均值柱 | 直方图／箱线／柱+散点 |
| 标签不压数据 | 阈值标注落在柱顶 | 见下「两条根因」 |
| 每图有 n | 图里图注都没有 n | 放进子图标题或图例 |
| 纵轴有单位 | 只写「数量」「公告数」 | 加单位 |
| 截断／封顶有标 | 封顶处的堆积柱读起来像峰 | 单独染色 + 图例写条数 |
| 窗口外样本有交代 | 子图只画一段，读者把柱高之和当成全样本 | 标题写「区间内 X 份，占 N 的 Y%」 |
| 子图之间可比 | 箱宽不同、轴范围不同，读者直接比高 | 图注声明不可直接比 |

最重的一条是「窗口外样本」：它不弄坏任何像素，但把一个子集读成了全集，是信息错误。

### 两条根因（都在脚本里）

**1. 标注位置不能按轴高比例放。**

```python
# 错：轴上限的固定比例，任何比它高的柱都会撞上，换数据就复发
ax.text(t + 1, ax.get_ylim()[1] * 0.9, f"{t}%")

# 对：先抬上限，锚在新上限上，或把偏移单位改成点
top = ax.get_ylim()[1]
ax.set_ylim(0, top * 1.22)
ax.annotate(f"{t}%", xy=(t, top * 1.13), xytext=(3, 0),
            textcoords="offset points", ha="left", va="center")
```

**2. 封顶堆积要单独成一个可见类别。**

`clip(upper=...)` 会造出一根没有对应的假峰。最后一个 bin 单独染色，图例写明规则与条数（「≥200%（截断，8 份）」）。两子图 bin 宽不同时也要说。

### 验收：先量后看

- 脚本层：`fig.findobj(Text)` 的 bbox 两两求交，撞了不算完。
- 像素层：PNG 逐张打开看。几何检查抓不到「字看着小」。
- 交付层：`docx`／`pdf` 的 mtime 晚于 `png`，否则交出去的是旧图。

## 二、附录：查的是「承诺」而不是「附录」

长稿压成期刊版时，最容易丢的是附录里的逐条明细表（复核明细、编码案例、样本损耗）。

它不会自己暴露，因为正文还留着那句承诺：

> 本文公开两层编码数据集与编码手册，供后续研究复现。

**查法：** grep `附录`、`Appendix`，再 grep 每一个 `公开｜提供｜详见`。**每个承诺都要在文件里找到兑现它的那张表。** 找不到就是压缩时丢了，不是「不必写」。

**为什么必补：** 稿子的卖点是「改判 7/15」这类比例，审稿人第一个问题就是「哪 7 条、凭什么改判」。没有逐条表，这个数只能靠读者信你；而且这类表往往只有一千多字符，成本极低。

**补回去之后必核四个数：** 改判条数与方向拆分、一致率、进回归条数（注意子样本口径与全样本口径不是一回事，别混）、个别样本的 CAR。附录与正文对不上，比没有附录更糟。
