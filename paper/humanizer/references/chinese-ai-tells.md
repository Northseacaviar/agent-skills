# 中文 AI 腔红线（来自用户 2026-10-17 反馈，message.txt）

这五条是判断「像不像人写的」的实操标准。写中文交付物（幻灯片正文、讲义、说明、汇报）时逐条自检。

## 1. 工业/机械隐喻
「链条、闭环、走完、拆解、颗粒度、落地、打通、赋能」这类词是互联网黑话 + 工程语。人会说「把前因后果理清楚」「把流程顺一遍」「最后总结一下」。
- ✗ 把整条链走完，结论压成一句
- ✓ 这篇论文把一件挺绕的事讲清楚了

## 2. 爹味/教导主任口吻
「有三件事要说在明处」「第一、第二、第三」「必须强调」「值得注意的是」。除非真在写公文，人不这么说话。
- ✗ 有三件事要说在明处。第一…第二…第三…
- ✓ 不过这篇也有它的边界。样本是 2013 到 2020 年的 15 次调样…

## 3. 抽象名词+四字成语的缝合物
「结论压成一句」「高度凝练」「本质上是」「某种意义上」。读起来塑料感重、没有信息增量。宁可多用动词和具体名词。
- ✗ 结论压成一句：名单把被动持股推上去
- ✓ 名单一动，被动资金跟着动；持股上去了，波动就小了

## 4. 没有废话和毛边
人说话会犹豫、会加语气词、会带自己的判断：「我觉得挺有意思的是…」「说不太准」「这里其实有点绕」。全篇零毛边=蒸馏过的纯逻辑，像合成肉。
- 允许并鼓励：我觉得 / 说实话 / 挺 / 有点 / 其实 / 你看
- 但别硬塞，每段一两处即可

## 5. 强行点题的讨好型升华
结尾非要把话拔高一句（「所以，我们要透过现象看本质」）。人早就懂了，被强行升华只会烦。
- ✗ 真要问市场因此更有效率没有，这篇答不了
- ✓ 所以这篇能回答的是「被动资金让价格平了一点」，回答不了「市场因此更有效率」

## 6. 语域选错：把「讲解」交成了「答题」

用户发来一道作业题（教材习题、分析题、案例）时，他要的是**能交上去的作答纸**，不是一节辅导课。这两样不是一个东西。

- **第一次就给作答版。** 先讲一通再等他说「我可以如何作答」，等于让他提两次要求。讲解放在作答之后，或者留给对话。
- 每题 3–6 行，一段一义。不要小标题 + 分点 + 加粗三件套。
- **表格换成句子。** 答题纸是手写的，抄表比写句慢；只有真正的数据对比才留表。
- 删报幕句（「这一问考的是」「本质上是」），直接给判断和依据。
- 末尾附「评分点」：这题考官会看哪几处（必须写出的公式、必须点到的两条机制），三五行就够。

同样适用反向：用户说「先讨论」时，一个工具都别动，也不要把讨论稿写成交付稿。

## 交付前自检（默读一遍）
1. 有没有一句是在「报幕」（这一页讲什么、压成一句、说明一下）？删。
2. 有没有为了节奏硬凑三连？能一句说完就说一句。
3. 有没有既不舒服也不推进的空转句？删或换实句。
4. 抽象词密度：一段里出现两个以上「本质/逻辑/机制/维度/层面」，改成人话。
5. 有没有一处属于「我自己的判断」或犹豫？没有就加一处真的。
